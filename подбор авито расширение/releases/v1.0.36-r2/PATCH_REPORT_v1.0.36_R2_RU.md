## Что исправлено

В v1.0.35 manifest объявлял 1.0.35, а настоящий Avito adapter отвечал 1.0.34. Worker корректно блокировал сбор с AVITO_ADAPTER_VERSION_MISMATCH_RELOAD_REQUIRED. В v1.0.36 обе версии 1.0.36; защиту worker не ослабляли. От v135 production-diff ограничен manifest.json и константой ADAPTER_VERSION. Capture, worker, core, proxy, recovery и popup побайтно прежние.

R2 отличается от первого кандидата v1.0.36 только тестовой очисткой уничтоженного Worker VM и связанными тестом/метаданными. Runtime R1 и R2 одинаков. При уничтожении test VM позднее продолжение больше не включает её таймеры снова. Нет принудительного process.exit(0), удаления assertions или увеличения лимита проблемного теста.

## НАРУШЕННЫЕ ПРАВИЛА И НЕЗАКРЫТЫЕ ОГРАНИЧЕНИЯ

Предыдущий процесс оставил GitHub без новых точных исходников (правила 17/19) и пропустил межкомпонентное расхождение версий в v135 (2/10/11). Эти исходные архивы сохранены как история; дефект версий воспроизведён и устранён в v136.

Первый кандидат v136 не был принят: тестовая VM после dispose повторно планировала callback и не давала процессу закончиться. Для R2 сохранён RED→GREEN тест очистки. Runtime-таймеры не изменялись.

Первый CI R2, run 34695322848, остаётся **34 PASS / 1 FAIL**: popup_lifecycle превысил 30 секунд, лог пустой. Его точная причина **не установлена**. Повторные успешные наблюдения не доказывают причину прежнего таймаута и не превращают старый отчёт в PASS. Старый результат сохранён в QA/final_zip/; новый — в отдельной QA/verification_34696794119_1/.

В текущем завершении не создавалась новая runtime-версия и не переписывался ZIP. Установленный пользовательский E2E по правилу 12 — **NOT_RUN**. Поэтому живая приёмка остаётся открытой, а слово «рабочий» к релизу без этой проверки не применяется.
