## Зачем v1.0.23

v1.0.22 ошибочно могла считать смену Proxy.Market profile_id доказательством смены реального внешнего IP и после этого снова reload Avito в тот же IP-block.

v1.0.23 вводит контракт:

`VERIFY EGRESS → RESET/ROTATE → VERIFY EGRESS → reload Avito only after verified recovery`

Ключевые правила:
- выбранный `rotation=0 / Каждый запрос` не переключается автоматически на Sticky;
- реальный egress проверяется через `api.ipify.org` / `api64.ipify.org`;
- provider `change_ip_link` сам по себе не считается успехом — нужен измеренный результат;
- при необходимости допускается один bounded fallback: новый `rotation=0` endpoint в уже существующем package;
- без подтверждённого recovery Avito не reload'ится;
- proxy transport errors входят в тот же recovery;
- `dom_probe_not_ready` во время незавершённой навигации считается transient;
- ZERO-MEDIA сохраняется;
- CAPTCHA остаётся ручной границей.

Live-acceptance смены egress должна подтверждаться реальным запуском по диагностическим markers; локальный QA не подменяет live-проверку Proxy.Market/Avito.
