## Почему был нужен v1.0.37

Живой v1.0.36 R2 run `af-20260912140042-p4kl` не смог прочитать ни одной карточки. Был сначала явный `AVITO_IP_BLOCK`, затем страница `IP_BLOCK + geetest CAPTCHA`. Popup показывал `PROXY_CONFIGURED_AVITO_IP_BLOCK_AUTH_NOT_OBSERVED`; при отчёте recovery attempt 3 сохранялась stale popup-запись attempt 2.

Аудит exact v1.0.36 R2 доказал семь классов proxy telemetry/state defects:

1. worker producer писал `probe_before/probe_after`, popup ожидал другой contract;
2. transport probe и target verification смешивались одним `ok`;
3. current attempt мог не сохраниться перед CAPTCHA terminal exit;
4. same-profile PAC reapply сдвигал `proxy_applied_at` и скрывал прежнее auth evidence;
5. `PROXY_CONFIGURED` не требовал exact Finder-owned PAC;
6. ошибки egress probes могли остаться только в коротком log;
7. mixed IP-block + CAPTCHA и manual gate переносились/показывались неполно.

На exact v1.0.36 R2 новые regression tests дают RED: static `0/10`, dynamic `0/6`. На v1.0.37 те же tests дают GREEN: `10/10 + 6/6`.

## Scope патча и anti-regression границы

Production runtime от v1.0.36 R2 изменён только в:

- `manifest.json`;
- `avito_content.js`;
- `service_worker.js`;
- `popup.js`.

Побайтно неизменны:

- `chatgpt_content.js`;
- `core.js`;
- `proxy_manager.js`;
- `recovery.js`;
- `popup.html`;
- `popup.css`.

Поэтому намеренно не переписывались:

- pre-proxy exact-target navigation lifecycle из v1.0.31;
- explicit queue/cursor/owned child semantics;
- report reconciliation без blind resend из v1.0.32;
- Writing Block-only command gate и manual CAPTCHA из v1.0.33;
- body stability / validation-before-ownership из v1.0.34;
- search methodology и baseline.

## Что исправляет v1.0.37

- exact PAC ownership/match используется при proxy diagnostic;
- transport probe results и Avito target status разделены;
- current recovery attempt сохраняется до CAPTCHA terminal report;
- probe IP/time/error сохраняются durable;
- auth evidence привязано к active profile epoch и не стирается внутренним same-profile reapply;
- popup показывает `IP BLOCK + CAPTCHA`, если оба признака видимы;
- manual CAPTCHA gate вычисляется до report staging clear и переносится через delivery;
- attempt >=3 без session provider key/package фиксирует explicit endpoint-create `SKIPPED` reason вместо молчаливого отсутствия mutation;
- stale persistent `key_check` больше не выглядит как текущий загруженный ключ.

API key остаётся session-scoped. Автоматическое решение CAPTCHA не добавлено. Blind DIRECT fallback и случайный profile failover не добавлены.
