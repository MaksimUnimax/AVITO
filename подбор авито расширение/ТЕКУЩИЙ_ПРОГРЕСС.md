## Причина v1.0.38 — уточнённая историческим аудитом

Exact v1.0.37 при escalation создавал residential recovery endpoint с `rotation:0` и принимал только профиль с `rotation_settings.rotate===0`.

В проектной/Proxy.Market семантике `rotation=0` — «Каждый запрос», то есть новый HTTP-запрос может получать новый pool IP. Для recovery Avito это не обеспечивает стабильную многозапросную сессию после IP-block.

Финальный RED ловит фактический provider create HTTP body:

- exact v1.0.37: actual `rotation=0`, expected `-1` → RED;
- v1.0.38: actual `rotation=-1`, reconciled sticky endpoint `rotate=-1` → GREEN.

**Уточнение после старта Rule-20 audit:** exact v1.0.23 и exact v1.0.24 уже содержат `rotation:0` для recovery-created endpoint и reconciliation `rotate===0`. Следовательно это старая policy lineage, а не новый дефект v1.0.37. Самая ранняя версия появления пока не установлена — аудит продолжается назад до первой proxy-версии.

Ранние невалидные RED/harness попытки не засчитаны и сохранены в истории. Полный разбор текущего release — `PATCH_REPORT_v1.0.38_RU.md`, но он **не заменяет Rule-20 full-history audit**.
