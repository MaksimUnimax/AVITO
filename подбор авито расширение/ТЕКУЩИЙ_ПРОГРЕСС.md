## Root-cause boundary перед v1.0.43

Exact v1.0.42 recovery code уже хранит:

- `probe_before` / `probe_after`;
- `probe_ip_changed`;
- `transport_status` + probe errors;
- `connection_recovery.create` / endpoint create state and reason;
- `provider_rotation` receipt;
- `last_ip_block_recovery`.

Но terminal `avitoRuntimeFailureReport()` эти данные не включал. В чат возвращался generic `AVITO_IP_BLOCK_RECOVERY_EXHAUSTED` + attempt count. Поэтому нельзя было честно выбрать между следующими failure classes:

- provider rotation ACK, но egress не изменился;
- session API key/package unavailable и endpoint create skipped;
- create dispatched but outcome unresolved;
- новый sticky endpoint применён, но egress не изменился;
- egress изменился, но новый IP также заблокирован Avito;
- Chrome CONNECT/session reuse;
- transport/auth failure.

Любой behavior patch на этом этапе был бы speculative.
