# Правила текущего поиска ПК — WORK ONLY

Актуально: 2026-09-08.

## 1. Область поиска

Только **WORK**.

Не вести и не пересчитывать GAMING / UNIVERSAL / BUDGET.

Цель: лучший готовый рабочий ПК на Avito строго в диапазоне **8 000–15 000 ₽ включительно**.

География: вся Россия.
Категория: настольные компьютеры.
Сортировка: по дате / новые сначала (`s=104`).

Приоритет:

**CPU → RAM → SSD/NVMe → платформа / надёжность / апгрейд → GPU**

Желательно:
- 16 GB RAM или больше;
- SSD/NVMe;
- сильный CPU;
- готовая рабочая конфигурация;
- без обязательного ремонта;
- без скрытой доплаты до заявленной конфигурации.

Игровая видеокарта сама по себе не делает лот сильным WORK-кандидатом.

## 2. ACTIVE WORK TOP

В ACTIVE WORK TOP допускается только лот, который прямо сейчас:

1. ACTIVE;
2. имеет живую публичную ссылку;
3. стоит **8 000–15 000 ₽ включительно**;
4. является готовым полным ПК;
5. имеет читаемый актуальный паспорт;
6. имеет подтверждённую прямую кнопку `Купить с доставкой` / эквивалентную прямую Avito Доставку;
7. не имеет критического конфликта характеристик и описания;
8. не требует обязательного ремонта;
9. не требует скрытой доплаты для получения заявленного ПК.

Не считаются подтверждением direct-доставки сами по себе:
- `Доставка от...`;
- `Скидка на доставку`;
- `Авито Гарантия`;
- `14 дней на возврат`;
- `Запросить доставку`;
- вопрос продавцу `Отправите Авито Доставкой?`.

## 3. Обязательная перепроверка TOP

Перед каждым новым основным циклом выполнять `TOP_REVALIDATE_PRE`:
- перечитать каждый лот ACTIVE WORK TOP через видимый Avito UI;
- проверить live-статус;
- цену;
- CPU/RAM/storage/platform;
- прямую Avito Доставку.

Если лот SOLD / REMOVED / UNAVAILABLE / ARCHIVED / URL_NOT_FOUND, вышел из диапазона 8–15k, потерял direct или materially изменил конфигурацию — он сразу перестаёт быть ACTIVE.

После detail новых кандидатов выполнять `TOP_REVALIDATE_POST` и строить финальный TOP заново только из живых подтверждённых лотов.

## 4. Основной цикл 3×50

Фиксированные широкие запросы, порядок не менять:

1. `пк`;
2. `компьютер`;
3. `системный блок`.

По каждому запросу получить ровно `CURRENT_50` уникальных карточек.

Схема:
- p1: собрать до 30 видимых объявлений;
- p2: собрать до 30 видимых объявлений;
- дедуп по listing ID;
- взять 30 с p1 + первые 20 уникальных с p2;
- p3 использовать только если p1+p2 не дали 50 уникальных.

Итого основной полный проход: **50 + 50 + 50 = 150 query-позиций**.

## 5. Collection stage

На collection-этапе:
- detail не открывать;
- карточки не сортировать вручную;
- хорошие/плохие не отбирать;
- ничего не пропускать из-за слабого железа;
- сохранять фактический порядок Avito.

По карточке сохранять как минимум:
- позицию;
- listing ID;
- публичный URL;
- заголовок;
- цену;
- город;
- видимый CPU;
- RAM;
- SSD/NVMe/HDD;
- текст доставки;
- краткое видимое описание;
- флаги: комплект / монитор / запчасти / неисправен / цена от / несколько конфигураций / противоречивый паспорт.

## 6. NEW-diff

После появления корректного baseline 8–15k:

`NEW = CURRENT_50 - OLD_50`

считать отдельно для каждого из трёх запросов, затем делать межзапросную дедупликацию NEW.

Старый baseline 0–15k нельзя использовать как авторитетный OLD_50 для нового диапазона 8–15k.

Первый полный 3×50 после смены диапазона является baseline-establishing run.

## 7. Detail

После collection detail открывать только у сильных WORK-кандидатов, которые реально могут:
- приблизиться к постоянному эталону;
- обойти текущий живой TOP;
- дать близкую рабочую производительность заметно дешевле;
- оказаться аномально выгодными и требовать проверки.

Не расходовать detail на заведомо слабые конфигурации, если они не улучшают текущий live benchmark по WORK/value.

## 8. Сравнение

Каждый сильный кандидат сравнивать одновременно:

1. с постоянным WORK-эталоном;
2. с текущим ACTIVE WORK TOP.

Если уже по карточке кандидат реально близок к эталону — сообщить сразу:

`🔥 WORK — БЛИЗКО К ЭТАЛОНУ`

Если после detail он превосходит эталон:

`🚀 НОВЫЙ WORK-ЭТАЛОН-КАНДИДАТ`

Сам постоянный эталон меняется только по явному решению пользователя после подтверждения полного паспорта, цены и direct-доставки.

## 9. Ограничения Finder

Работать только через видимый/public Avito UI и DOM.

Запрещено:
- hidden Avito API;
- сообщения продавцам;
- открытие телефона;
- покупка;
- автоматическое решение CAPTCHA.

CAPTCHA: вернуть `CAPTCHA_MANUAL_REQUIRED` и ждать ручного действия пользователя.

При `AVITO_IP_BLOCK` использовать текущий recovery Avito Finder v1.0.23 и продолжать текущий запрос без сброса уже собранного прогресса.
